# 次优库种子格式规范（M07）

次优库只放**通用原则与回答框架**，展示标签统一为“通用建议”。每个岗位一个文件：`seeds/secondary/<岗位标签>.md`
（`tech.md` `product.md` `ops.md` `mgmt.md` `general.md`）。新增岗位 = 新增一个文件 + 审核，无需改代码。
本目录的 `README.md` 不会被解析/扫描。全部内容自编，不得复制任何第三方题库。

## 文件结构

- 文件内可有 `# 标题`、`## 分类` 与任意说明文字；**只有 `### Q…` 块被解析**，块之外的文字被忽略（但仍会被合规扫描）。
- 每题一个块，字段**每行一个标签**，冒号用 `:` 或 `：` 均可，字段顺序建议如下：

```
### QTECH-01 讲讲 CAP 理论
变体:
- CAP 三个字母分别指什么
- 分布式系统里一致性和可用性怎么取舍
- 网络分区发生时系统该怎么办
结论: 一句话结论（说清核心立场）。
要点:
- 第一条，一句话。
- 第二条，一句话。
- 第三条，一句话。
示例: [需本人补充：与该主题相关的项目经历]
注意: 一句话提醒（常见误区/不要夸大/需本人补充）。
岗位: tech
类型: 知识
```

## 解析与校验规则（tools/scan_seeds.py 与导入器共用同一解析器）

| 项 | 规则 |
|---|---|
| 标题 | `### Q<大写字母2-6位>-<数字2-3位> 问题文本`，如 `QTECH-01`、`QGEN-12`、`QPM-03`、`QOPS-07`、`QMGT-05`；题号全库唯一（建议前缀：技术 TECH、通用 GEN、产品 PM、运营 OPS、管理 MGT） |
| 变体 | `变体:` 后接 3-5 条 `- ` 列表，每条是同一问题的不同问法 |
| 结论 | 单行非空 |
| 要点 | `要点:` 后接**恰好 3 条** `- ` 列表，每条一句话 |
| 示例 | 单行，**只能**是 `[需本人补充：…]` 占位（可连写多个），冒号后写要补充什么，不得含数字、公司、人名 |
| 注意 | 单行非空 |
| 岗位 | 逗号分隔的小写标签（`[a-z][a-z0-9_]{1,15}`），如 `tech` / `tech, pm`；**必须包含本文件名（去掉 .md）对应的标签**；通用题用 `general`（general 题在任何岗位会话都会被检索到） |
| 类型 | 四选一：`知识` `行为` `情景` `观点` |
| 字段缺失/重复/多余行 | 一律报错，该题不会被导入 |

岗位隔离：会话选定岗位集合 R，检索范围 = 标签与 R 有交集的题 ∪ `general` 题。想让某题被多个岗位共用，在“岗位:”里列多个标签。

## 数量下限（扫描脚本检查，统计“岗位标签含本文件名”的题数）

`tech` ≥ 60，`pm` ≥ 60，`ops` ≥ 60，`mgmt` ≥ 60，`general` ≥ 40；新岗位默认 ≥ 60。

## 内容红线（扫描脚本自动检查，违规即非零退出）

1. 不得出现具体人名、公司名（含“某某有限公司”）、内部项目名。公共技术/方法论名词（如 CAP、Redis、OKR）可以。
2. 不得出现业绩数字：百分比、金额、具体年份（“2023 年”）、“提升/增长/降低 + 数字”、“营收/DAU/GMV + 数字”等。
   公共知识数字（三次握手、状态码 200、端口 6379 等）在白名单内；确需新增请在报告里说明，由主线加入白名单。
3. 不得出现第一人称经历句（“我/我们 + 做过/负责/主导/带领/曾…”、“我在 XX 公司…”）。写框架，不写经历；
   经历一律放进“示例”占位里让本人补充。建议句式用“可以说明…”“建议先…”“避免…”。
4. 不得虚构任何个人事实；要点写**原则/步骤/判据**，不写“结果数字”。
5. 要点、结论保持一句话、可扫读。

## 自检与导入

```
.venv/bin/python tools/scan_seeds.py              # 扫描 seeds/secondary，零违规且题数达标才算完成
.venv/bin/python tools/scan_seeds.py <dir> --min pm=60
```

导入：`POST /api/secondary/import`（读取 seeds 目录，新条目为 pending，需人工 `POST /api/secondary/{id}/review` 批准后才参与检索）。
内容变更的题重新导入后回到 pending。
