# 访谈提示板：项目详细说明

## 1. 这是什么

访谈提示板是一个本地运行的面试实时提词系统。它在面试过程中听对方提问，判断问题何时问完，
从你事先审核过的题库里找出对应的回答要点，显示在提示板上。

- 服务只监听 `127.0.0.1:8765`，数据存在本机 `data/` 目录。
- 提示内容来自你自己的资料，不是模型凭空生成。个人经历类问题永远不会用通用答案或联网结果顶替。
- 云服务是可选项，默认开启，每一项都可以关闭，关闭后回退到本机模型。

适用于：用自己的复盘资料准备面试，并在线上或线下面试中作为参考提示。
不适用于：多用户部署、公网暴露、需要账号体系的场景。

## 2. 端到端流程

1. 导入资料：把面试复盘整理成 Markdown 导入，系统拆成一问一答的条目，状态为"待审核"。
2. 审核题库：逐条确认事实，把可用条目启用。只有"已启用"的条目会参与检索。
3. 会前准备：选择资料、目标岗位、线上或线下模式，确认音源，必要时登记声纹，核对本场外发开关。
4. 开始会话：在会话页授权麦克风和会议音频，点击开始采集，计时从采集开始算起。
5. 实时提示：对方提问被转写并判定结束后，提示板先显示候选卡片，按 `Enter` 采用后成为主提示；回答者开口回答后，主提示在本题内不再被替换，新结果只作补充。
6. 结束会话：采集停止并保存，计时立即冻结，可导出 Markdown 记录，在记录库回看。

## 3. 核心能力

### 3.1 音频采集与模式

| 模式 | 音源 | 角色判定 |
|---|---|---|
| 线上 | 麦克风（回答者）+ 会议音频（提问方） | 按通道区分 |
| 线上，只有麦克风 | 单麦混音 | 声纹门控：已登记声纹时区分提问方、回答者和不确定 |
| 线下 | 房间麦克风，一路混音 | 声纹逐段判定角色 |

- 网页会议可共享浏览器标签页音频；桌面客户端需要虚拟声卡（如 BlackHole），详见 `docs/M02-7_会议客户端兼容矩阵.md`。
- 浏览器端通过 AudioWorklet 采集，按 20 ms 一帧（16 kHz，PCM16）经 WebSocket 发给后端，帧带序号，断线重连后可补发缺口。
- 后端把音频按帧落盘为 WAV，记录缺口，并有回声检测（外放且未戴耳机时提示）。

### 3.2 转写

- `asr.backend`：`auto`（有云 Key 且外发开关开启时用阿里云实时转写，否则用本机 sherpa-onnx）、`aliyun`、`sherpa`。
- 云转写失败、被外发开关关闭、或预算不足时自动降级到本机模型，并在界面上提示。
- 热词从已启用条目中规则提取并下发给云转写，回答者代号不会下发。
- 单麦或线下模式下混音只有一路，开启云转写会包含你自己的声音。

### 3.3 提问结束判定

两阶段：先出"候选"，再"提交"。候选可以被撤销，已提交的题可以回滚。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `T_silence` / `T_long` / `T_hard` | 200 / 700 / 1500 ms | 静音判定的三档时长 |
| `T_answer_silence` | 1500 ms | 回答方静音多久算回答结束的必要条件 |
| `T_new_turn` | 1200 ms | 新一轮提问的间隔 |
| `max_turn_ms` / `max_turn_chars` | 30000 ms / 200 字 | 单轮最长时长与字数 |
| `monologue_segments` / `T_monologue` | 3 段 / 10000 ms | 单麦连续独白门控 |

- 回答方开口后，提问方插话先分类：附和语气词保持当前答案，追问或改题才打断。
- 单麦模式下连续多段被判为提问方（对方在长篇独白）时暂停提词，界面提示"检测到连续独白，已暂停提词"。
- 服务默认以本地 VAD 静音为主触发（`trigger='vad'`，对所有会话生效）：提问方静音达 `T_silence` 就取当前最新转写判定，不等转写追上句尾。
  这样出提示更快，但转写可能还没跟上，所以结果先作为"候选卡片"显示，按 `Enter` 确认后才升级为主提示；未确认的候选在新题提交或本轮关闭时清理。
  转写追上后若语义不变，文本会原地更新；语义变化则回滚，并如实计入"过早提交"统计。
- 轮次参数是默认值，未经真实面试数据标定。

### 3.4 检索与提示分层

提问先做意图分类（优先级：流程 > 个人经历 > 观点判断 > 行为情景 > 知识概念），再按子问题分别检索。

| 级别 | 含义 | 展示方式 |
|---|---|---|
| L1 | 主库命中 | 主提示 |
| L1p | 真实部分覆盖，有关键词证据 | 只展示命中部分，不当标准答案 |
| L1c | 高分但并列，或没有关键词证据的弱匹配 | 作为候选，不当标准答案 |
| L2 | 次优库命中（通用建议） | 标"通用建议" |
| L3 | 联网补充，仅限知识和观点类 | 补充区，后台任务 |
| personal_miss | 个人或行为类未命中 | 诚实框架，提示需要本人补充，不联网 |
| miss / skip | 无结果 / 流程性发言 | 不提示 |

- 个人经历和行为情景只走主库，永远不用次优库或联网结果替代。
- 检索用向量（bge-small-zh-v1.5，512 维，sqlite-vec）加关键词（FTS5 trigram）融合，再经相关性过滤，过滤短实体名不匹配的结果。
- 含 `[待核]` 标记的条目会红标展示，不计入主库完成度（G3），也不会以"我的口吻"直接呈现。
- 联网和模型补充只产出补充内容，不替换主提示；回答结束、改题或重新提交时会取消。
- 防串题：回写前比对当前活动题和任务序号，不一致只归档不推送。

### 3.5 题库与审核

- 主库：每场会话绑定一个，来自你自己的资料。次优库：按岗位的通用原则与框架（`seeds/secondary/`，全部自编）。
- 条目状态：待审核、已启用、已拒绝。启用前必须确认事实和保留的待核提醒，并提供审核答案。会话进行中，本场题库冻结。
- 可选的模型增强：把条目拆成问法变体、回答要点（结论、要点、例子、注意事项）、事实和标签。提示词要求"只整理、不创作"，输出经格式校验后，再按同一条目的原文出处比对事实，疑似编造的会被标记且不能启用。
- 跨条目冲突检测，以及批量启用资格检查。
- 资料更新走版本化重导入：未变条目继承审核状态，变更和新增条目回到待审核。

### 3.6 隐私与外发

默认开启的三项外发（均可在设置页和每场会话前关闭，本场只能关闭不能再打开）：

| 开关 | 发给谁 | 内容 |
|---|---|---|
| `outbound.asr_audio` | 阿里云实时语音识别 | 会议或房间音频 |
| `outbound.llm_snippets` | DeepSeek | 识别出的问题和题库片段；题库增强还会发送条目，手机号、邮箱、证件号、银行卡号会先遮盖 |
| `outbound.web_questions` | DeepSeek Search | 脱敏后的知识类问题 |

另有 `outbound.asr_answerer`（默认关闭）只控制回答者逐字稿是否写入记录与导出，不控制音频是否上传。

- 联网前脱敏：邮箱、证件号、银行卡、手机号、公司名、URL 里的用户信息，以及资料词表里的姓名、公司、项目；命中本场专有词或个人经历意图的问题整题不外发。正则不能保证内部知识已脱敏，这是已登记的风险。
- 日志脱敏：Key 样式、Bearer、手机号、邮箱和自定义词表；日志目录权限 700；WebSocket 地址里的 `token` 在 uvicorn 日志中以 `***` 显示。
- 凭证读取顺序：环境变量、macOS 钥匙串、`data/.env`；凭证面板保存后输入框清空，接口响应不返回明文。
- `model.base_url` 和 `search.endpoint` 只接受 https 地址（本机回环地址可用 http），不接受带账号密码的地址。
- 本地接口防护：只接受 `127.0.0.1` 和 `localhost` 主机头；非 GET 的 `/api/*` 请求要求每次启动随机生成的 `X-Local-Token` 并检查 Origin；WebSocket 自行校验 Origin 和 token。这是防跨站请求，不是登录认证。

### 3.7 预算

- 云转写、模型、搜索各有估算额度（单位：元）：搜索加模型每日 20、每场 5；云转写另有独立的每日 5、每场 1.5；并发请求数上限 4。
- 额度用尽时降级而不是中断：云转写回退到本机模型，模型和联网跳过。
- 单价（`prices.*`）是估算占位值，用量页明确标注"估算，非计费硬保证"，使用前请改成真实单价。

### 3.8 状态与降级

每个能力（采集、转写、角色、检索、模型、搜索、声纹、磁盘等）独立维持 ok、degraded、down 三态，某一项降级只影响依赖它的功能。
会话页状态条用指示灯展示，并给出单麦门控统计、本场外发状态和提示板连接状态。

### 3.9 记录与导出

- 每场会话保存逐字稿、系统提示、事件、录音和缺口，记录库可回看。
- Markdown 导出把"实际发言"和"系统建议"分章节，不混写，只输出白名单字段，不含声纹模板、配置快照和 Key。
- 时长口径：从首个实时音频帧到会话结束；结束时间由服务端写入。

## 5. 架构

```
浏览器（TypeScript）
  采集页 AudioWorklet ──20ms PCM 帧──► /ws/audio/{session}
  提示板 ◄──────── 事件与提示 ───────── /ws/board/{session}
                                          │
FastAPI 后端（127.0.0.1:8765）            ▼
  AudioHub：落盘、去重、补洞、缺口记录
    └► SessionPipeline：VAD → ASR → TurnDetector（按通道或声纹区分角色）
         └► AnswerLoop：意图分类 → 三级路由 → 提示事件
              ├ 检索：bge 向量 + FTS5 关键词（只检索已启用条目）
              ├ L3 联网、模型补充（后台任务，受预算与外发开关约束）
              └► EventBus ──► 提示板
  支撑：配置与凭证、预算与用量、能力状态板、记录库、埋点、日志脱敏
```

目录：

- `app/`：`api` 接口、`asr` 转写适配、`audio` 采集与声纹、`domain` 轮次与角色判定、`library` 题库与增强、`realtime` 会话编排、`retrieval` 检索路由、`search` 联网、`llm` 模型客户端、`privacy` 脱敏、`records` 记录与导出、`sessions` 会前准备、`health` 能力状态、`telemetry` 埋点
- `web/`：页面与 TypeScript 源码，编译产物 `.js` 同目录
- `tests/`、`tests_web/`：后端与前端测试
- `tools/`：评测、标定、模型下载、密钥扫描
- `eval/`：合成数据评测与报告；`seeds/`：次优库种子；`models/MANIFEST.json`：模型清单与哈希

## 6. 接口概览

- HTTP：`/api/libraries`（题库与条目）、`/api/sessions`（会话、快照、导出、录音）、`/api/setup`（会前准备）、`/api/profiles`（回答者资料）、`/api/voice`（声纹）、`/api/config`、`/api/credentials`、`/api/usage`、`/api/search`、`/api/status`
- WebSocket：`/ws/audio/{session}` 收音频帧；`/ws/board/{session}` 推送提示事件，并接收显示确认和候选采用
- 音频帧：24 字节头加 640 字节 PCM16 载荷；头里有来源（mic、meeting、room）、流编号、代数、序号、客户端时间戳和重放标记

## 7. 技术栈与本地模型

- 后端：Python 3.13、FastAPI、uvicorn、SQLite（sqlite-vec、FTS5）、httpx
- 前端：TypeScript（tsc 编译，无打包器和框架）、Playwright 做 e2e
- 本地模型（约 360 MB，不随仓库发布，用 `tools/fetch_models.py` 下载并校验 sha256）：

| 模型 | 用途 | 许可证 |
|---|---|---|
| Silero VAD | 语音活动检测 | MIT |
| bge-small-zh-v1.5 | 句向量检索 | MIT |
| sherpa-onnx streaming paraformer 中英双语（int8） | 本机转写 | 以上游为准，未核实 |
| 3D-Speaker CAM++ | 声纹 | 以上游为准，商用前需复核 |

## 8. 安装、运行、测试

见 `README.md`。要点：`pip install -r requirements.txt`、`npm install && npm run build`、`tools/fetch_models.py`、`python run.py`。
后端 `pytest -q`；前端 `npm test`（编译、单元测试、Playwright e2e，实测约 1 分钟，视机器而定）。

## 9. 当前状态与已知限制

- 只在 macOS（Apple Silicon）上开发和测试。
- 真机场景尚未系统验证：扬声器回声、各会议客户端、30 分钟以上连续采集。
- 轮次判定参数没有用真实面试语音标定。检索阈值（`tau_cos` 0.74、`tau_cos_strong` 0.80、`tau_mid` 0.62、`margin` 0.03）是在规则式改写的评测集上选出的，
  不代表真实语音和转写噪声：留出半区命中 235/244（约 96%），库外误认 0/61，样本量有限，0 误认的 95% 置信上界仍约 5.9%。
- 各项单价是估算占位值。
- 云转写和 DeepSeek 都需要自备 Key；没有 Key 时转写回退到本机，提示生成和联网不可用。
- 服务没有账号体系，请不要把端口转发到其他机器。
- 部分 GET 接口（快照、导出、录音）不要求 token，因为服务只监听本机，风险有限，但共享机器上不建议使用。
- 首页的视频、海报、logo 和三款字体来源未核实，不在 MIT 范围内。维护者决定按现状发布（2026-11-09），素材集中在 `web/landing/assets/`，收到权利人异议时立即替换。

## 11. 合规提示

- 录音前请取得所有参与者的知情同意。
- 请确认你所在地区和所在公司对录音、使用第三方云服务、在面试中使用辅助工具的规定。
- 默认配置会把音频发给阿里云、把片段发给 DeepSeek。不接受这一点就在设置页关闭对应开关，或不配置 Key。
- 本工具提供的是参考提示，回答的内容和后果由使用者自己负责。
