# 模块工作原理

配套《项目详细说明.md》阅读。前者讲"系统能做什么"，本文讲"每个模块内部怎么做到的"：职责、核心文件、关键机制与参数。全部内容基于实际代码。

## 0. 一条音频帧的旅程（端到端数据流）

```
浏览器 AudioWorklet（音频线程，每 512 样本回调）
  → downmix + Kaiser 窗 sinc 重采样到 16 kHz
  → 20 ms 成帧（24 B 头 + 640 B PCM16LE）
  → WebSocket /ws/audio/{session} 二进制上行
→ AudioHub：StreamRecorder 按 seq 落 WAV（原位补洞/缺口记录）；live 帧交 SessionPipeline
→ 按通道路由（generation 变更即重置并平移时钟）→ VadSegmenter 产出 speech_start/end
→ 提问方 PCM 推 ASR（本地 sherpa 或云转写）→ TranscriptEvent
→ TurnDetector 两阶段判定（音频毫秒时钟）→ candidate / committed / rolled_back
→ EventBus.pull() → ① board_ws 推给提示板渲染 ② AnswerLoop：
    split_clauses → classify_intent → 向量+FTS5 RRF 检索 → classify_hit → Router
→ 主答案 / 候选卡片 / 状态经 EventBus 下发（防串题双闸）；
  L3 补充后台任务先 redact 脱敏再联网/调模型
→ 全程 Metrics.mark 埋点，供导出与评测报告。
```

## 1. app/audio — 音频接入、落盘、VAD、声纹、回声

核心文件：`frame.py`、`recorder.py`、`vad.py`、`voiceprint.py`、`enroll.py`、`echo.py`。

- **帧协议**（`frame.py`，与前端 `web/capture/frame.ts` 字节级互为镜像）：24 字节头 + 640 字节 PCM16LE 载荷（320 样本 = 20 ms @ 16 kHz）。头含 magic `IA`、版本、来源（mic / meeting / room）、重放标志、stream_id、generation、seq、48 位客户端微秒时间戳。
- **落盘**（`StreamRecorder`）：以 `seq` 直接映射 WAV 文件偏移——重放帧原位补洞，重复帧丢弃，从未填写的区间即缺口（`gaps()` 可导出）；每 10 分钟（30000 帧）切片，每写 50 帧刷新一次 WAV 头防崩溃损坏；上限 2 小时。
- **VAD**（`VadSegmenter` 状态机）：优先 Silero（512 样本 / 32 ms 窗 + 64 样本上下文），缺模型自动降级为纯 numpy 能量判决（320 样本窗，噪声底上升每窗 +2%、下降即时跟随）。输出 `speech_start / speech_end` 事件，`pre_roll 300 ms / min_speech 60 ms / hangover 100 ms`。
- **声纹**（`voiceprint.py` + `enroll.py`）：CAM++ ONNX 抽 192 维 embedding；登记质检顺序为"有效语音 ≥8 s → SNR ≥12 dB → 三子段两两余弦 ≥0.6"，模板只存本机 SQLite（目录 0700），永不入日志与导出。
- **回声检测**（`EchoDetector`）：对 mic/meeting 两路做 1 s 滑窗 FFT 归一化互相关（max_lag 200 ms），相关系数 >0.6 持续 ≥3 s 判外放回声，提示"可能未戴耳机"，恢复时发 cleared。

## 2. app/asr — 流式转写（本地 / 云）与降级

核心文件：`base.py`、`sherpa.py`、`aliyun.py`、`metered.py`、`hotwords.py`。

- **统一事件**：`TranscriptEvent`（source / text / is_final / text_version 句内递增 / audio_covered_until_ms / t_audio_start_ms / t_audio_end_ms / t_received_ns），两种后端都归一到"音频毫秒"时间轴。
- **本地后端**（`SherpaStreamingASR`）：paraformer 中英 int8 流式；无字级时间戳，`audio_covered_until_ms` 用 `已喂音频 - 600 ms lookahead` 作保守下界；推理放单线程池，push 串行保序。
- **云后端**（`AliyunRealtimeASR`）：run-task → task-started → 二进制 PCM → result-generated → finish-task 协议；begin/end 时间加上首个推送时刻统一到会话时间轴；错误分 auth / rate_limit / timeout / other，日志先脱敏 Key。
- **重连与降级**（`ReconnectingASR`）：0.5 / 1.0 / 2.0 s 退避；重连期间音频直接丢弃，text_version 以 `_floor` 接续保证跨重连单调；`MeteredASR` 按字节计量（32000 B/s），预算耗尽时无缝切回本地 sherpa 并在界面提示。
- **热词**（`hotwords.py`）：纯规则——英文技术词、书名号专名、出现 ≥3 次的 2~8 字中文片段；score = 频次 ×（1 + 长度/10），映射为 1~5 权重下发云转写，上限 500 词；纯数字与含 @ 的词丢弃，**回答者代号永不进入热词**。

## 3. app/domain — 轮次判定、语义分类、打断、角色

核心文件：`turn_detector.py`、`semantic.py`、`interrupt.py`、`roles.py`、`speaker_roles.py`。

- **两阶段状态机**：`idle → listening_question → question_candidate → question_committed → answering`（`waiting_continue` 是附加标志非独立状态）；时间全部用调用方传入的音频毫秒，不读墙钟，便于回放评测。
- **关键参数**：`T_silence 200 ms`（提交静音）、`T_long 700 ms`（低完整度长静音）、`T_hard 1500 ms`（未完成句硬超时）、`coverage_slack 100 ms`；回答阶段 `T_answer_silence 1500 ms`、`T_new_turn 1200 ms`、单轮上限 30 s / 200 字。触发模式 `coverage`（等转写覆盖）或 `vad`（服务默认：静音达阈值即取最新转写，先出候选，快但可能早，靠回滚兜底）。
- **撤销与回滚**：commit 后提问方重新开口 → `rolled_back`；迟到 final 改变语义要素（否定词 / 子问题数 / 尾部 bigram 重叠 <0.5）→ 回滚；语义不变且编辑距离 ≤2 → 原地 `text_updated`。恒等式 `premature_count = resume + semantic + late` 三类回滚之和。
- **语义分类**（`semantic.py`，纯正则）：question / request / statement / process / backchannel + 完整度 high / low / incomplete；附和与流程性发言不成轮。
- **打断分类**（`interrupt.py`）：回答中提问方开口先判 backchannel（<1 s 附和）/ followup（bigram 相似 ≥0.5 或"那…呢"句式）/ switch（终止语 + 完整新问题）/ new_question；switch 立即换题，其余进待答队列，等回答方静音达 `T_answer_silence` 后弹出。
- **角色判定**：线上按通道（mic=回答者、meeting=提问方）；线下 `SpeakerRoleTracker` 每 500 ms 滚动提取声纹（窗 0.8~3 s），滚动相似度均值 ≥0.55 判回答者、≤0.35 判提问者，同段既高又低判 unknown；声纹不可用时降级为能量 + 上下文推断（低置信）。

## 4. app/retrieval — 检索、融合与三级路由

核心文件：`index.py`、`search.py`、`router.py`、`intent.py`、`clauses.py`、`precheck.py`、`tags.py`、`thresholds.json`。

- **双路召回**：FTS5 `tokenize='trigram'`（<3 字查询降级 LIKE）+ bge-small-zh-v1.5 向量（sqlite-vec 余弦，缺扩展时 BLOB + numpy 回退）；问句与问法变体分别入库；`index_version` = 内容 sha256 + 模型 revision + tokenizer 标签，不匹配即全量重建。
- **RRF 融合**：`score = Σ 1/(60 + rank)`，两路各取 top20，条目取两路中的最佳排名；只有向量 `cos` 可与阈值比较。
- **L1 命中三证据**（`classify_hit`）：① cos_top1 ≥ 0.74；② FTS 对该条目有词面命中或 cos ≥ 0.80；③ cos_top1 − cos_top2 ≥ 0.03。三条不全则降级：并列高分/无词面证据 → L1c 候选；部分覆盖且有证据 → L1p。
- **路由优先级**：先拆子问（问号/句号/分号/换行及"以及/另外/然后/同时"，不拆"A 和 B 的区别"），逐子问意图分类（process > personal > opinion > behavior > knowledge）。个人/行为类只走主库，未命中给 personal_miss 诚实提示，**永不**用次优库或联网顶替；知识/观点类先查次优库（cos ≥ 0.62 判 L2 通用建议），否则 L3 联网。
- **防误配**（`precheck.py`）：部分命中能否复用看四条件——相似度 ≥0.9、尾句已覆盖、否定词一致、子问题数一致。`[待核]` 条目永不冒充"我的口径"，只标"含待核内容"。

## 5. app/library — 题库解析、版本化、LLM 增强

核心文件：`parser.py`、`versioning.py`、`facts_extract.py`、`conflicts.py`、`enhance.py`、`enhance_llm.py`、`secondary.py`。

- **解析拆条**：附录格式 `**H编号｜时间｜问题** 参考回答：…`，逐条记录行号区间；正文含"待核"即 flagged；编号重复直接报错。
- **版本化重导入**：`library_sources`（只读触发器）/ `library_versions` / `entry_versions` / `facts` 按版本存档；重导入按内容 hash（NFKC + 空白归一后 sha256）继承审核状态、已确认答案与增强结果，未命中回 pending；会话激活时库冻结，开会时 `freeze_session` 固定版本与已启用条目 hash。
- **事实比对**：规则抽取 project / metric / role / time / org 五类事实（含条目内出处）；LLM 输出中的数字、项目名、机构名按条目定位——同条目找到通过、只在别的条目 `cross_entry`、完全找不到 `suspected_fabrication`，红标且禁止启用。
- **冲突检测**：同项目 + 同单位（数值替换为 `#` 归一）+ 数值不同 → 同一 conflict_group。
- **LLM 增强**（DeepSeek）：提示词"只整理、不创作"，temperature 0.1，输出经手写 schema 校验（恰好 3 条回答要点、3~5 个问法变体）；无 Key / 外发关闭 / 预算拒绝时保留规则拆解结果，增强只是锦上添花。

## 6. app/realtime — 会话编排、提示闭环、防串题

核心文件：`pipeline.py`、`answer.py`、`events.py`、`audio_ws.py`、`board_ws.py`、`answer_web.py`。

- **SessionPipeline**：replay 帧直接跳过；每个 (stream_id, generation) 一条路由，新 generation 重置并以当前会话时钟平移；线上 meeting=提问方（VAD+ASR 喂检测器）、mic=回答方（VAD 驱动"回答结束"判定）；线下 room 段经 SpeakerRoleTracker 判角色，未定前转写暂存，确定后补喂；单麦门控——连续 ≥3 个提问方段且 10 s 内无回答方 → 判独白，暂停提词并提示。
- **AnswerLoop**：订阅轮次事件，逐子问检索（专用单线程执行器跑 sqlite）；主答案取第一个命中 L1/L1p/L2 的子问；VAD 主导提交先发 `prompt_candidate`（按 Enter 采用才升级主提示）；**主答案本题内锁定**——回答开始后新结果只作补充，不替换。
- **防串题双闸**：回写前比对 (turn_id, epoch) 与任务序号，不一致只写 late_archived；发布层 publish 再丢一次。epoch 在新题提交时递增，回滚后重提交沿用 turn_id 只增 epoch。
- **EventBus / board_ws**：event_seq 单调，保留最近 200 条供 snapshot + since 重放恢复；board_ws 每 100 ms 拉取一次，握手必须带同源 Origin + token，校验失败 close(4403/4404)。
- **L3 联网补充**（`answer_web.py`）：从主库提取公司/项目名作封锁词表（命中整题不外发）、回答者姓名删除；无 transport / 开关关闭 / 预算拒绝直接返回状态文本；个人经历类根本不进入联网分支。

## 7. app/sessions — 会前准备与自检

核心文件：`setup.py`、`selfcheck.py`、`profiles.py`、`probes.py`。

- 会话生命周期 draft → ready → active → stopped，同一时刻仅一个 active；setup 接口对 sessions 表幂等扩展列。
- **自检**：检查项按 online/offline 过滤，`asyncio.gather` 并发，单项超时 3 s、总超时 10 s，结果 PASS/WARN/FAIL；FAIL 映射为提示板顶部常驻降级标识。
- **探测原则**：llm_ping 无 Key 判 FAIL、外发关闭判 WARN 不发请求、有 Key 才短超时探测（Key 绝不进 detail）；本地 sherpa 按三文件齐全判 PASS；search 按次计费默认不探测。

## 8. app/privacy — 外发前脱敏

核心文件：`privacy/redact.py`。

- 规则按"长数字先于短数字"顺序执行：email → 身份证 → 银行卡（16~19 位）→ 手机号 → 公司名；资料词表分两类——专有词（terms）命中**整题 blocked**，姓名/公司/项目（names 等）命中只从文本删除；单字别名不参与替换。
- 个人经历意图模式（"你负责 / 你们项目 / 自我介绍"等中英文）命中即 blocked，调用方不得发起任何外发。
- 模块自述局限：正则无法保证内部知识已全部脱敏，这是文档中如实登记的风险。

## 9. app/records — 记录、导出、删除

核心文件：`records/store.py`、`export.py`、`bundle.py`、`review_edit.py`。

- 会话记录用独立 SQLite：逐字稿 segments（编辑保留 orig_text 并在 segment_edits 留痕）、turns（含 t_candidate/t_committed/t_visible 完整时间戳）、turn_events、prompts（display_ack 幂等键唯一约束）。
- **导出**：Markdown 只输出白名单字段，"实际发言"与"系统建议"分章节绝不混写；声纹模板、配置快照、Key 永不进入导出；bundle = transcript.md + metrics.csv + 各路 WAV（1 MB 分块流式写入）+ manifest.json，录音逐个校验 RIFF/WAVE 头标 ok/missing/corrupt。
- **删除两步制**：request 发 token → confirm 凭 token 把数据 dump 成 session.json、录音移入 trash 回收目录，不直接物理删除。

## 10. app/health — 能力状态板

核心文件：`health/monitor.py`、`capabilities.py`、`faults.py`。

- 8 个能力（capture / asr / role / retrieval / llm / search / voice / disk）各自独立维持 ok / degraded / down，`DEGRADE_MATRIX` 定义"某故障 → 受影响能力 + 系统行为 + 提示文案 + 提示时限"（如转写断连：继续录音、保留当前答案、3 s 内提示）。
- 监测节奏：llm/search 每 10 s 周期探测（独立任务、2 s 超时）；ASR 停滞 = 本地 VAD 判有语音且 3 s 内无任何 partial/final（静音不误报）；音源 2 s 无帧判丢失；磁盘 <1 GB WARN、<200 MB 告警。
- 错误分类只看异常类型与 HTTP 状态映射 14 类错误码，**不读异常文本**，避免凭证外泄。

## 11. app/telemetry — 埋点、回放、评测

核心文件：`telemetry/metrics.py`、`replay.py`、`report.py`。

- metrics 单表 `(session_id, turn_id, name, t_ns, value)` 即写即 commit；`clock_offset` 用往返最小样本估计浏览器与后端时钟差（误差上界 = rtt/2）。
- 回放器按实时节拍重发带 replay 标志的帧（默认不进 VAD/ASR，live 模式才当实时流）；批次测量误差上界 = chunk_ms，报告中如实标注。
- 报告：线性插值分位数 + Wilson 置信区间；判定规则 PASS（达标且 n≥30）/ PROVISIONAL（n<30）/ FAIL / NOT TESTED / SIMULATED（**合成链路永不判 PASS**）；门槛提示判定 P95 ≤300 ms。

## 12. 凭证 / 预算 / 配置

核心文件：`credentials.py`、`usage.py`、`config.py`。

- **凭证**：读取顺序 环境变量 → macOS 钥匙串（可选）→ `data/.env`；明文只在进程内流转，不进 HTTP 响应、日志与异常；界面只显示末 4 位掩码。
- **预算**：请求前 reserve（占在途名额与估算额度），结束 settle 或 cancel 释放；ASR 有独立日/场限额，搜索/模型超额不挤停转写；单价是可改的估算占位值。
- **配置**：`config.default.json` + 用户 `data/config.json` 合并，手写 schema 校验（点分键 → 类型/范围）；`model.base_url` / `search.endpoint` 只接受 https（回环可 http）且不带账号密码；会话开始时冻结快照，运行中不读热配置。

## 13. web/ — 浏览器端（无框架，tsc 直编）

核心文件：`capture/pcm-worklet.ts`、`frame.ts`、`framer.ts`、`sender.ts`、`resampler.ts`；`board/reducer.ts`、`client.ts`、`keys.ts`。

- **采集链**：AudioWorklet 音频线程每 512 样本回传 → downmix + floatToPcm16 → Kaiser 窗 sinc 流式重采样（192 tap，任意分块输出逐位一致）→ 20 ms 成帧 → 与后端字节级镜像的 24B+640B 帧上行。
- **断线重放**：每源保留 30 s / 1500 帧缓冲，server ack_seq 释放；重连后 generation+1、seq 归零，缓冲帧带原编号与 replay 标志重放补洞；close 1003/1008/4403/4404 视为致命不重试。
- **提示板**：`reducer.ts` 纯函数状态机（与服务端发布层双重校验 prompt 规则），snapshot 恢复 + since 重放；快捷键 Esc/H 隐藏恢复、F/Shift+F 四档字号、Enter 仅在有 VAD 候选时采用。
- **构建**：无打包器无框架，`npm run build` 即 `tsc --target ES2022 --outDir web`，产物 .js 与 .ts 同目录；测试 `node --test tests_web/*.test.mjs`。
