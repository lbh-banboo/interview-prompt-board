- macOS 14.2+（系统音频共享依赖该版本以上的系统能力）；Chrome >= 141。

## 实测步骤（每个单元格）

1. 在目标客户端加入一个有对方发声的会议（或播放一段已知有声内容的测试会议），确保对方声音通过系统输出。
2. 在产品页面点击“选择会议窗口/标签页/屏幕”，在系统选择器中选对应共享方式，并勾选“共享系统/标签页音频”。
3. 获取到 MediaStream 后检查：
   - `stream.getAudioTracks().length > 0`；
   - 接入 AudioContext/AnalyserNode，3 秒内 RMS 出现非零能量（对方发声时）。
4. 结束后立即停止所有轨道，记录结果与现象。

## 判定标准

- PASS：`getAudioTracks().length > 0` 且 3 秒内 RMS 有非零能量。
- FAIL：音轨数为 0（未勾选或客户端不提供音频），或有音轨但 3 秒内 RMS 恒为 0。
- 失败时产品必须提示“未获得会议声音，请重新选择并勾选共享音频”，不得假装已采集。

## 已知限制

- `getDisplayMedia` 不能只请求音频（`video:false` 会报错）：请求 `video:true`，拿到流后立即停用并移除视频轨，仅保留音轨。
- 用户共享时未勾选音频，则零音轨；必须提示重选。
- 共享方式不同，是否带音频由浏览器与操作系统决定，不能由页面强制。
- 授权不可持久，每次会话需重新点击授权。
- **2026-11-04 实测（macOS Chrome，本机会话录音电平检查）**：共享“整个屏幕/窗口”时 `getAudioTracks().length > 0`，但音轨整体全零（19.6 s 会议录音 RMS=0）；仅共享“Chrome 标签页”并勾选“共享标签页音频”才有声音。桌面客户端（腾讯会议/飞书/Zoom）的系统声音浏览器抓不到。该条只记录现象，不改变矩阵中仍为 NOT TESTED 的单元格；正式结论需按上文步骤逐项复测。
- 桌面客户端的可选路径是虚拟声卡回环（如 BlackHole 2ch），页面将该设备作为“会议音频”输入并关闭回声消除/降噪/自动增益；本仓库未在任何真实环境实测该路径。

## 检测辅助（待前端实现的判定逻辑，不在本文件范围内实现）

- 零音轨 -> 提示重选；音轨存在但 3 秒无能量 -> 同一提示（并在电平表显示静音）。
- 音轨 `ended` 或连续 2s 无帧 -> `source_lost`，后端由 `HealthMonitor.on_source_frame` 在 2s 内判定“会议音频已断开”。

## 线下单麦外放（offline 模式，2026-11-07 新增）

方案：对方声音**外放**，只用一路麦克风（帧头 `source=room`）同时收录双方，由声纹（M03-4 SpeakerRoleTracker）区分谁在说话。前端会话页线下模式只显示"一路麦克风（同时收录双方）"，不再提供会议音频来源。

### 前提与设置

- 会话以线下模式创建，且建议先在会前配置向导完成"声音登记"（3 段朗读，模板仅存本机）。
- getUserMedia 约束：room 通道**关闭** `echoCancellation` / `noiseSuppression` / `autoGainControl`。依据：外放时浏览器 AEC 会把扬声器放出的对方声音当回声减掉（正是"对方声音进不来"的典型原因）；降噪/自动增益会改变远场人声频谱与电平，而声纹相似度阈值与 `min_rms` 均按原始输入设计，登记与采集也使用同一套关闭处理的输入链（`web/capture/constraints.ts`）。
- 引导条第 3 步"确认外放测试"只检测外放能量，**无法在本页区分是谁在说**，通过后仍需用户自行确认。

### 限制（全部 NOT TESTED，未做真实环境实测）

- 真实外放回声：关闭 AEC 后，回声会同时进入录音，后端无线上 EchoDetector 可用；对转写与声纹的实际影响未测。
- 真实两人声纹区分准确率：两人声音相近、音量接近或同时说话（overlap）时区分会变差；`high/low/min_rms` 等阈值仍是待标定默认值（M14 / tools/calibrate_voiceprint.py）。
- 真实麦克风（远场拾音距离、指向性、系统输入增益）未实测；上表"虚拟声卡输入"列的实测方法同样适用于本模式的麦克风选择，但结果未填写。
- 声音登记质量阈值（有效语音 ≥8s、SNR ≥12dB、三段互相似度 ≥0.6）为待标定默认值，不是验收结论。
